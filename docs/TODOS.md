# Project TODOs and Future Enhancements

This document outlines planned features, potential improvements, and known limitations for the Halal Random Strings project. Contributions are welcome for any of these items!

## High Priority

*   **Refine `words.json` categories and rules:** Continuously review and improve the categorization of words and the rules for combining them to ensure more meaningful and diverse string generation.
*   **Implement more sophisticated word combination logic:** Explore algorithms that can generate more grammatically correct or contextually relevant multi-word strings beyond simple concatenation.
*   **Add more comprehensive word lists:** Expand all existing categories with more words, especially for less populated ones, and introduce new relevant categories as needed.

## Medium Priority

*   **Implement string length control in `main.go`:** Allow users to specify `min_words` and `max_words` directly from the CLI for more flexible generation.
*   **Add a `dry-run` mode for `populate_d1.py`:** Allow users to see the SQL commands that would be executed without actually performing the database operations.
*   **Implement a `check-d1-schema` command in `populate_d1.py`:** Verify if the D1 database schema matches the expected `schema.sql` before population.
*   **Add API Key/Authentication to Cloudflare Worker:** Secure the API endpoints to prevent unauthorized access.

## Low Priority

*   **Support for different separators:** Allow users to specify custom separators (e.g., `_`, `.` instead of `-`).
*   **Web UI for string generation:** Create a simple web interface for users to generate strings interactively.
*   **Integrate with CI/CD pipelines:** Automate the generation, analysis, and D1 population process within a CI/CD pipeline.
*   **Internationalization (I18n):** Explore supporting word lists in other languages.

## Known Limitations

*   **Current word combination is basic:** Strings are generated by concatenating words from selected categories, which might occasionally result in less natural-sounding phrases.
*   **`crypto/rand` fallback:** While `crypto/rand` is used for the uniqueness suffix, the word selection still relies on `math/rand` for performance. This is generally acceptable as the uniqueness is guaranteed by the suffix.
*   **No built-in string expiration/cleanup:** The D1 schema includes `used_at` and `used_by` fields, but there's no automated process to expire or clean up old/unused strings.
